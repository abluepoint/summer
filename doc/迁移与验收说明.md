# Summer 4 迁移与验收说明

## 构建基线

- Java toolchain：21。
- Gradle Wrapper：9.0.0，Kotlin DSL。
- Spring Boot：4.0.7。
- Spring Cloud：2025.1.2。
- Spring Modulith：2.0.7。
- 源码版本：`4.0.0-SNAPSHOT`。

版本单点位于 `gradle/libs.versions.toml`；`summer-dependencies` 导入 Boot、Cloud、Modulith BOM 并约束全部 Summer 发布模块。

## 迁移约定

- 核心模块旧源码与 POM 作为语义和历史实现参考；`summer-data-jpa-test` 的旧 Maven POM、`src/main` 示例与旧 SQL 已删除。
- Summer 4 核心模块从 `src/boot4/java`、`src/boot4/resources` 编译；测试从 `src/boot4Test` 编译。
- `summer-automator` 不在 `settings.gradle.kts`，不会参与核心构建或发布。
- 新业务只接入 Gradle 模块和 starter，不再以 `summer-parent/pom.xml` 为入口。

## 验收命令

```bash
./gradlew clean check
./gradlew publishToMavenLocal
./gradlew :summer-data-jpa-test:bootJar
```

`check` 必须包含并通过：模块依赖白名单、公共能力单测、请求体重复读取、SQL 渲染、Tuple 多形态映射、Spring Modulith、真实 PostgreSQL Testcontainers、OAuth2 令牌签发、受保护 SQL 查询、401/校验响应和 Actuator 健康/指标。

## 已知边界

- 示例使用内存客户端/用户与进程内临时 RSA JWK，生产必须替换为持久化或外部安全设施。
- 旧 API 二进制兼容、独立微服务部署和大规模性能压测不属于本次范围。
- 旧 Maven 构建不再是交付门禁；Gradle `check` 是唯一核心验收入口。
