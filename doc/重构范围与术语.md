# Summer 4 重构范围与术语

## 能力边界

| 旧能力 | 决策 | Summer 4 落点 |
| --- | --- | --- |
| Maven 父工程与分散版本 | 替代 | 根 Gradle Kotlin DSL、版本目录、`summer-dependencies` |
| 统一错误码、消息、上下文 | 重构保留 | `summer-common` 与 `summer-common-starter` |
| 请求体缓存、参数校验、统一响应 | 重构保留 | `summer-mvc`、`summer-web-autoconfigure`、`summer-web-starter` |
| JPA 实体、Repository | Jakarta 化重构 | `summer-data-jpa` 与 `summer-data-jpa-starter` |
| Freemarker 动态 SQL | 重构保留 | `SqlTemplateSource`、`FreemarkerSqlRenderer`、`JpaSqlTemplate` |
| Tuple 到 Bean/Map/List/接口 | 重构保留并补 Record | `TupleMapper` |
| JSON 登录、私有 JWT/JTI | 剔除 | 统一由 OAuth2/OIDC Authorization Server 与 Resource Server 替代 |
| 登录/鉴权错误 JSON 化 | 重构保留 | `JsonAuthenticationEntryPoint`、`JsonAccessDeniedHandler` |
| starter 空壳 | 替代 | 四类 autoconfigure、四类 starter、聚合 starter |
| JPA 示例素材 | 替换 | 删除旧 Maven POM、`src/main` 示例与旧 SQL，仅保留可运行、可鉴权、可查询、可观测的 Modulith 示例 |
| `summer-automator` | 归档 | 保留源码，不进入核心 `settings.gradle.kts` |
| 全量历史 API 兼容 | 不在范围 | 核心模块旧源码已清理；标准 `src/main`、`src/test` 仅保留 Summer 4 实现 |

## 统一术语

| 术语 | 定义 |
| --- | --- |
| Core module | 不依赖 starter 的领域能力库，只暴露稳定 API。 |
| Autoconfigure | 根据 classpath、Bean 与 `summer.*` 开关条件化注册基础设施。 |
| Starter | 只聚合依赖与自动配置，不承载业务实现。 |
| Aggregate starter | `summer-boot-starter`，一次引入完整 Web/Data/Security/Actuator 能力。 |
| Application module | Spring Modulith 识别的业务包边界，通过 `package-info.java` 声明。 |
| Infrastructure seam | Core 与应用之间由 autoconfigure/starter 连接的装配边界。 |
| Authorization Server | 负责 OAuth2/OIDC 客户端、授权、令牌签发与元数据端点。 |
| Resource Server | 校验访问令牌并保护 `/api/**` 等资源端点。 |
| SQL template | classpath SQL 资源中以 `-- templateName` 分段、由 Freemarker 渲染的查询。 |
| Unified response | `success/data/error/requestId/timestamp` 稳定结构；协议端点和 Actuator 不包装。 |
| Fail closed | 安全能力显式开启后，缺少客户端等关键配置会阻止应用启动。 |

## 明确非目标

- 不保持旧 JSON 登录、私有 JWT/JTI 类和外部 API 的二进制兼容。
- 不把授权服务拆成独立部署单元；当前在同一应用内通过安全过滤链隔离。
- 不让 `summer-automator` 进入核心发布链。
- 不以单次大规模性能测试代替架构、集成和端到端验收。
