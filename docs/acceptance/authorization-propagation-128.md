## 设计与实现

角色、接口、菜单、数据策略变更在 MySQL 事务内先写审计，再写带资源版本、租户、
requestId 的 outbox。Redis Stream 至少一次投递，每个节点有独立消费组；先清除
本地缓存投影，再使用持久化 receipt 保持业务消费幂等。HTTP 判定每次重新读取持久
授权，因此旧 JWT 不会仅因 Redis 丢失通知而永久保留撤销权限。参见
[ADR 0027](../adr/0027-versioned-authorization-change-stream.md)。

本轮三处最小修复：缺失消费组从 `0-0` 创建，避免 Redis 数据丢失后重建组跳过
已恢复发布的首条事件；可见前端每 10 秒及 focus/恢复可见时重读当前菜单与动作；
读取增加 10 秒超时，失联时清除旧访问，恢复后重读。初次加载以外不重复提交 manifest。
菜单内容不变时不重建页面，保留未提交表单。真正撤权或读取失败时关闭访问，草稿
保留不能覆盖这个安全边界。后台标签页计时器可能被浏览器节流，不承诺硬实时。

## 七条 AC 对应

1. **事件追踪与幂等**：正式角色变更产生带 requestId 的 outbox；实际 Stream 投递与
   receipt 可追踪，重复记录被 ACK 且只有一条持久 receipt，不重施旧拒绝。
2. **其他节点拒绝旧权限**：节点 A 撤权，节点 B 使用原 Bearer 返回 403；恢复角色后
   同一令牌按当前持久授权读取。接口角色与参数 CREATOR/TENANT 策略改变均有实际 HTTP。
3. **重复/丢失/Redis 恢复**：重复、receipt 故障 pending、相同节点重启无新事件恢复、
   删除真实流记录后数据库补偿已验证；Redis 重建消费组有效红灯已修复，新候选真实恢复及两节点 ACK 检查通过。
4. **缓存与审计**：实际 Redis 授权缓存版本增加，审计时间不晚于对应 outbox；outbox
   表故障返回 500，受影响角色内容/版本与该资源审计条数回滚。不扩称全业务表比较。
5. **真实前后端**：本地 MySQL 实际迁移、独立 Redis、两个 JVM、正式 PKCE、扫描权限
   目录及 Chrome；覆盖匿名 401、无权 403、未知资源 404、非法策略 400、真实故障 500。
6. **契约与敏感信息**：校验 SUMMER_ 错误码、成功/失败信封、请求头与响应体 requestId，
   事件仅含规定元数据；密码与 Token 留在进程内。代理故障只悬停真实上游响应。
7. **可追溯交付**：逐批机器回执、原红灯、实际 XML、执行脚本快照和截图保留；绿色
   Chrome 正常关闭，各批资源清理 VERIFIED，敏感日志检测无命中。尚未执行最终全仓门禁。
