## 修复后的行为

菜单覆盖在数据库中裁决版本。首次创建通过现有 manifest 行锁保护；既有覆盖执行版本条件更新，未命中返回 `412 SUMMER_PRECONDITION_FAILED`。回执只在事务提交后发布。真实 MySQL 和两个 JVM 的首次、既有写入竞争均为一个 200、一个 412，只有胜者产生一条变更审计和一条 outbox。

事务尾部故障通过独立数据库账号暂缺 outbox 插入权限注入。真实 HTTP 返回 `500 SUMMER_INTERNAL_ERROR` 后，版本、排序、审计和 outbox 均保持原值；恢复账号权限后，在同一 JVM 使用相同幂等键重试成功，版本和两类记录各增加一次。没有改写业务表制造授权或数据。

客户菜单的 `read/create/update/delete` 动作来自既有 `AuthorizationService.decision`，并同时满足实际接口所需 scope。请求过 OAuth write scope 不再等于获得业务写权限。真实只读主体拥有角色中的 POST 能力但被显式拒绝时，服务端只返回 read，客户页面无新增、编辑、删除按钮，直接 POST 仍返回 `403 SUMMER_FORBIDDEN`；允许新增的管理员可见新增按钮。

导航和路由共同使用当前活动租户的服务端可见菜单，组件始终由本地路由解析。停用客户抽屉菜单后，导航入口消失，直达路径显示拒绝页。本地父分组采用精确匹配；即使字典父菜单仍启用，停用的子路径也不会被父页面接住。最终截图已原生目视核对。

## 故事和实现

设计依据为 [ADR 0026](../adr/0026-use-versioned-route-menu-manifest.md)。故事24由路由生成manifest，故事25由安全元数据和本地组件解析落实；故事26由菜单管理、数据库版本裁决和事务回执落实；故事27由 `src/menu/access.ts`、主入口、路由布局及客户按钮落实；故事28继续由既有后端授权强制执行。准确代码路径和每条缺陷的对应检查在 JSON 中。
