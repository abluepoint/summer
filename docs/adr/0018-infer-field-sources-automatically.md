# Infer Field sources automatically

Field 与 FieldList 的参数来源由框架自动推断，移除两者公开的 `source` 配置属性，不保留手动指定来源的入口；每个字段仍保持明确、完整的契约，完整性不等于逐项手写框架可以确定的属性。该决定替代 [ADR 0013](0013-expand-parameter-contracts-to-json-and-path.md) 中要求开发者显式选择来源的用法，内部仍区分 PARAM、JSON、PATH 输入及其不同语义，具体支持范围见下文；接受框架承担推断复杂度以减少重复配置。来源按字段在实际请求中的位置识别，不固定为某个 HTTP 方法对应某种来源，当前实现尚未迁移。

## 按实际请求推断

- 字段只在一个来源出现：读取该来源的值，再按字段契约校验。
- 字段未出现：按该字段的必填规则处理。
- 字段在多个来源出现：按下述来源冲突规则返回 400。

同一接口的同一个字段允许在不同请求中来自不同位置。例如一次通过查询参数提交 `email`，另一次通过 JSON 提交 `email`，均可按相同字段契约处理；单个请求同时从两处提交则拒绝。该规则不会自动改变 Style、presence、nullability 或未知字段策略，不提供显式来源覆盖能力；请求体缓存按后续 [ADR 0021](0021-manage-request-body-caching-automatically.md) 由 MVC 自动管理，移除旧开关及其专属启动检查，联动实现尚未完成。

移除 source 属性属于注解 API 变更。后续须删除现有 Field/FieldList 声明中的 source 赋值，并同步依赖该属性的运行时读取、未知字段检查、启动期缓存检查和测试；不能只删除调用方配置而继续按旧默认 PARAM 处理，也不新增另一套手动来源配置来替代 source。

## 同名跨来源冲突

同名字段出现在多个输入来源时，拒绝请求并返回 HTTP 400 来源冲突，不按来源优先级静默覆盖或合并。例如 URL 查询参数与 JSON body 同时提供 `email` 时，框架不得自行选取其中一个值。这是请求输入的歧义处理规则，不等同于当前实现对注解中重复导出名的配置冲突检查。

## PATH 仅支持单值字段

路径变量只承载单值 Field；集合仅通过 Query、表单或 JSON 传递，不再支持 PATH FieldList。来源自动推断必须遵守此范围，不能把路径变量解释成集合或集合数量；普通 Field 对路径变量的读取与校验继续支持。例如订单 ID 可以来自 `/orders/{orderId}`，订单明细集合通过 Query/表单索引字段或 JSON 数组提交。

当前 FieldList 仍允许声明 `source = PATH`，现有测试包含读取路径数量变量的用法；后续须迁移这些声明和测试，并取消 PATH 集合读取能力。本次仅记录决定，尚未修改注解、运行时或测试。
