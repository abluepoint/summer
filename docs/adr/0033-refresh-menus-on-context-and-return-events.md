# ADR 0033：按上下文与返回事件更新菜单，不定时轮询

- 日期：2026-10-19
- 状态：接受
- 替代：ADR 0027 中前端每 10 秒读取菜单的策略；服务端事件流决策不变

## 背景

用户明确要求 `/api/v1/enterprises/{enterpriseId}/menu-manifest` 不得定时访问。原页面外壳在初始化后建立 10 秒轮询，即使用户没有操作也重复读取清单。

## 决策

1. 移除页面外壳的菜单轮询，不以定时器或自动重试循环调用菜单清单。
2. 登录初始化、活动租户或身份上下文变化时读取清单；返回窗口焦点或页面从隐藏恢复可见时补读。当前上下文内的权限管理相关写入成功、菜单关联保存，以及非显式访问探测的业务 403，通过绑定 contextVersion 的本地失效事件补读；旧上下文事件不刷新当前清单。菜单管理页的显式读取和保存后刷新保留。
3. 保留并发读取保护、卸载与旧租户响应失效、请求超时、读取失败时清除旧权限，以及清单不变时保留页面和未提交表单的行为。
4. 不承诺停留在同一个前台页面时，远端授权变化会在固定时间内更新菜单。后端对每次业务请求独立鉴权，不依赖前端菜单更新。

## 验证

真实 React 页面外壳测试推进 60 秒而不产生额外菜单请求；触发窗口 focus 后读取一次，再推进 60 秒仍无定时请求。既有切换租户、身份更新、拒绝响应与卸载测试继续覆盖事件驱动更新的边界。
