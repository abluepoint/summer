# 退休旧数据权限菜单及策略管理接口

状态：已接受，2026-11-20 用户要求移除无实际作用的数据权限菜单并清理后端接口。

旧 `/data-scopes` 页面在 MANAGED 模式只引导用户进入权限管理，移除此独立入口、语言项、请求封装与管理菜单注册。

移除 `/api/v1/enterprises/{enterpriseId}/data-scopes` 下全部列表、详情、策略写入、审计、预览及主体绑定接口，以及专用 DTO 和服务读写逻辑；已认证请求返回 404。客户端和服务端默认 OAuth scope 清单不再申请或声明旧 `enterprise.data-scope.read/write`。

数据权限继续在 `/permissions` 中按业务资源、操作和预设范围管理，`/data-resources` 及权限自身的 `/permissions/{permissionId}/data-scope` 接口保留。当前行级过滤、租户隔离、组织校验、角色授权与迁移比较使用的历史表达式保持有效。历史表和迁移文件不删除、不重写；旧审计实体保留用于历史结构兼容。此决定延续 ADR 0039，替代 ADR 0028 中旧策略管理接口继续开放的安排。

共用活动企业选择迁到 `src/hooks/useActiveEnterprise.ts`，保留原有切换、未保存和写入保护。部署时通过正式菜单清单接口发布去除 `data-scopes` 的新版本；接口目录扫描会将已经卸载的 handler 标为 inactive，历史授权关联不会转移到其他接口。

测试应覆盖旧路由全部退出及历史数据不变，并继续验证当前数据范围、撤权和跨租户隔离。旧数据权限页面的历史验收记录保留，但不能作为当前页面验收证据。
