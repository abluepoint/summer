# ADR 0042：平台管理与租户管理采用独立功能入口

- 日期：2026-11-20
- 状态：接受，依据用户明确要求。

## 决策

角色管理、权限管理、菜单管理分别提供平台入口与租户入口。每个页面的授权域由入口固定，不提供平台/租户下拉框、页内切换按钮或无租户时自动切换到平台的行为。

| 功能 | 平台入口 | 租户入口 |
| --- | --- | --- |
| 角色管理 | `/platform/roles` | `/roles` |
| 权限管理 | `/platform/permissions` | `/permissions` |
| 菜单管理 | `/platform/menu-manifest` | `/menu-manifest` |

租户页沿用顶部活动租户；未选择租户时提示选择且不读取平台数据。平台页固定使用 PLATFORM 域，不显示租户选择框。平台清单发布与租户菜单布局编辑分别保留原有 API、并发版本、幂等和未保存修改保护。

## 授权与导航

现有菜单授权已按完整 Domain 隔离。为保留既有关系，服务端菜单资源 ID `roles`、`permissions`、`menu-manifest` 不改名；前端把 PLATFORM 域当前导航响应中的这三个资源映射到独立 `/platform/...` 路径，把 ENTERPRISE 域响应映射到租户路径。平台路径是本地路由别名，不作为重复资源写入全局菜单清单。

有活动租户时，导航分别读取该租户和平台域的当前资格；只有平台域响应可产生平台管理入口。平台导航拒绝或不可用时隐藏平台入口，保留有效租户导航。保留 enabled、navOnly、pageEligible 判定；目录资格不得升级为页面资格。两域 API 始终分别鉴权，菜单资格不授予接口权限。

菜单刷新仍遵循 ADR 0033 的初始化、上下文、返回窗口和本地失效事件机制，不增加定时轮询。此决定细化 ADR 0026 的本地路由映射，不改变 ADR 0039 的权限、角色和资源关联模型。

## 权限与资源目录

依据用户后续确认，导航增加一个“权限与资源”目录，下设“接口目录”“菜单管理”“权限管理”三个子菜单。菜单管理或权限管理同时存在平台与租户资格时，其子菜单继续展开到各自独立入口；只有一个域可见时直接进入该域页面，页面内不提供域切换。角色管理保持独立。

目录仅在已有可见子项时出现。先完成现有服务端菜单资格校验，再进行本地导航分组；新增目录不作为可授权页面、不写入全局菜单清单，不修改现有资源 ID、路径及授权关系。直接打开、刷新或异步加载菜单时，按真实菜单父子关系展开目录并标记当前页面。
