# ADR 0043：权限定义仅由平台维护

- 日期：2026-11-20
- 状态：接受，依据用户要求“权限管理只保留一个平台的，不需要租户自定义权限”。

## 管理入口与写入边界

“权限与资源”下只保留一个“权限管理”子菜单，进入 `/platform/permissions`，固定使用平台 API。租户导航返回的旧 `permissions` 资格不再生成租户页面，也不能换取平台页面资格；旧 `/permissions` 地址不再进入管理页面。平台入口仍须具备平台域当前授权。

租户不再创建、修改或删除权限及权限组，也不能修改权限关联的接口、菜单或数据范围。服务端对这些租户写入请求统一拒绝，不因已有管理权限、旧令牌或直接调用 API 而放行。平台写入继续执行原有鉴权、并发版本、幂等和审计契约。

## 平台目录与租户角色

用户进一步确认：“统一使用平台权限，租户只配置角色和人员授权”。权限组和权限的选择列表统一来自平台目录；租户角色页通过已有的角色列表接口读取分配选项（查询参数 `catalog=permissions` 或 `catalog=permission-groups`），校验当前租户的角色读取资格。租户权限及权限组管理路由已移除。平台可关联平台及租户的已登记接口、共享菜单资源，配置以当前使用租户为边界的数据范围（本人、全部、本部门、本部门及下级）；平台模板不嵌入某个租户的指定部门 ID。

新增 `summer_role_platform_permission` 持久关系，由租户域和角色外键确定归属，权限外键固定指向 `PLATFORM:platform`。租户新授权仅选择平台目录；平台角色继续按原关系保存。角色绑定、身份有效性、租户成员状态和 OAuth 委托上限保持独立校验。租户角色不能在另一租户或平台请求中生效。

授权计算读取当前平台定义，不复制权限。平台停用或修改权限立即影响引用它的租户角色；诊断和数据读取同时检查平台目录版本，数据写操作先锁平台目录再锁租户域，避免读后撤销与写入竞态。

## 历史关系兼容

新增迁移只建共享授权关系表，不删除或自动改写历史权限、内置引导关系、资源关联、角色及人员绑定。历史租户授权保留兼容读取，在角色编辑页单独显示“历史授权（可保留或移除）”；它只能留在已有角色中或被移除，不能复制给新角色。历史权限不会因此变成平台权限，也不会获得跨租户效力。历史指定部门范围继续按原租户解释。

## 与既有决定的关系

替代 [ADR 0042](0042-separate-platform-and-tenant-management-entries.md) 中权限管理同时提供平台和租户入口的部分；角色管理、菜单管理仍保留独立域入口。“权限与资源”的目录结构继续保留。

收窄 [ADR 0039](0039-manage-permissions-independently-of-resources.md) 的权限定义维护边界，不改变菜单、接口和数据权限分别授权、角色授予、域隔离及保存后即时生效的语义。
