# Summer 4 产品范围

Summer 4 是可复用框架。统一术语见 [CONTEXT](../../CONTEXT.md)，决策关系见 [ADR 索引](../adr/README.md)，代码状态见 [现状与目标差异](现状与目标差异.md)。

## 保留与重构的能力

| 能力 | Summer 4 落点 | 约束 |
| --- | --- | --- |
| 构建与依赖治理 | Gradle Kotlin DSL、版本目录、summer-dependencies | 不维护 Maven parent |
| 错误、消息、统一响应契约 | Common | 不成为工具箱或业务上下文袋 |
| 请求关联、请求体缓存、Field/Style、错误与响应 | MVC | PARAM/JSON/PATH，与 Bean Validation 并存 |
| 实体与 Repository | Data JPA | Jakarta；应用拥有具体实体和事务 |
| Freemarker SQL template | Data JPA | 复杂读取，与 Repository 写模型并存 |
| 查询结果投影 | SQL template 内部适配器 | 仅 ADR 0007 列出的形态 |
| OAuth2/OIDC、资源保护、可选授权服务 | Security 与其自动配置 | 协议原生；默认不启用授权服务 |
| 按需接入 | 四类 autoconfigure/starter、聚合 starter | 能力、装配和入口分层 |
| 可运行参考后端 | Summer Sample | Customer、operations、框架集成验证 |
| 可交互参考前端（目标） | 独立 summer-ui | 官方 Arco Pro；public PKCE；不属于 Java 框架能力 |

旧 JSON 登录、私有 JWT/JTI、JSON Schema 校验、静态应用上下文、旧 Maven 示例不恢复；历史实现通过 Git 追溯。Automator 作为独立产品/仓库演进，不建立 legacy/archive 代码目录。

## 框架与业务产品

AICT IAM 的企业、成员、组织、邀请、应用、Agent、策略、MCP 执行授权与审计属于产品模型。AICT BFF 的 Product Session 和连接服务的凭据、token vault、物理会话、重试同样归产品。已有方案来自本地工作区尚未提交的 `docs/specs/aict-unified-identity-technical-design.md`，该文件不包含在本次架构文档提交中；当前工作区 Sample 中的产品实现需要迁移，不提升为 `summer-security` 或 `summer-common` 能力。

Summer UI 与 AICT Console 分开：前者是 Arco Pro + 浏览器 public PKCE，后者的已有方案是 Vben + 同源 BFF。二者均消费框架，不能混用登录、会话、前端组件和部署约定。

## 当前目标中的非目标

- 不承诺旧 API 二进制兼容；Customer 从 email 到 username 为协调性破坏变更。
- 不增加 Customer 与登录主体/账号/企业的绑定、角色管理或 IAM 管理 UI。
- 不删除框架的 confidential client 能力；仅在迁移后移除 Sample 中的旧客户端实例。
- 不为 Sample 引入生产数据库迁移、持久化身份/JWK/授权仓储或完整生产运维系统。
- 不拆出通用 DTO、全局 Context、通用映射框架或无消费者的扩展接口。
- 不要求框架参考应用立即微服务化；AICT 独立连接服务的部署边界属于其产品方案。
- 不把前端纳入 Gradle 或 Sample JAR，不新增 Docker/Kubernetes/云/CI/CD 交付范围。

本次交付为分支与架构基线整理；运行时代码迁移和前端实现按 [迁移计划](../guides/summer4迁移计划.md) 分阶段完成。
