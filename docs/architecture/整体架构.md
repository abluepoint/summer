## 1. 产品与应用职责

| 层次 | 拥有的职责 | 使用关系 |
| --- | --- | --- |
| Summer 4 框架 | 错误/响应契约、MVC 参数与请求处理、JPA/SQL 读取、安全协议接入 | 对外发布平台、能力、自动配置与 Starter |
| Summer Sample | Customer 参考业务、运行信息、框架能力集成验证 | 通过 Starter 消费框架，不被框架依赖 |
| Summer UI（目标） | 官方 Arco Pro 基线、Customer 操作、浏览器 OIDC/PKCE 与后续 AICT 身份管理页面 | 仓库内唯一前端应用；经 HTTP 消费服务，不进入 Gradle 模块图 |
| AICT IAM 产品 | 企业、账号、成员、组织、应用、Agent、策略、委托、审计 | 复用框架；产品模型不进入 Common/Security |
| AICT BFF 与连接服务 | BFF 持有产品会话；连接服务持有物理连接、凭据、MCP 执行与回执 | 通过显式 HTTP/端口契约协作，拥有各自部署和数据责任 |

框架保持单一工程领域上下文，由根 CONTEXT 和 ADR 管理。AICT 产品不因暂时放在 Sample 包下就成为框架能力；其实现仓库和迁移落点需要单独落实，迁移必须完整保留既有源码和验证资产。

## 2. 构建与依赖设计

保留当前扁平的 15 个 Gradle 子项目，不为重整增加无职责的 `core`、`shared`、DTO 或父模块。Java 代码统一使用 `src/main/java`、资源使用 `src/main/resources`、测试使用 `src/test`。

- **能力模块**隐藏实现复杂度并提供窄公共 Interface：Common、MVC、Data JPA、Security。
- **自动配置模块**拥有 Spring Boot 条件、配置绑定、Bean 默认值和覆盖规则；能力模块不反向依赖装配。
- **Starter**只组合依赖。聚合 Starter 组合四种能力 Starter，并接入 Actuator。
- **依赖平台**发布版本约束，不是运行时根模块。BOM 中的 project constraints 不构成能力依赖环。
- **Sample**为可执行 Spring Boot 应用；发布配置排除 Sample，其余模块发布 Java 库或平台。

`settings.gradle.kts` 管理聚合；根构建管理编译、测试、发布与依赖白名单；版本目录记录内部版本；`summer-dependencies` 对外发布约束。当前保持根构建，未来共享规则确有独立复用需求时再提取 `build-logic` convention plugin。

精确模块表、允许依赖和检查限制见 [模块边界](模块边界.md)。

## 3. 能力 Interface 与职责

| 能力 | 调用方需要知道的 Interface | 隐藏的 Implementation / 限制 |
| --- | --- | --- |
| Common | `ErrorCode`、`ErrorCategory`、`SummerException`、`MessageResolver`、`ApiResponse`、`ApiError` | 消息解析与稳定传输契约；不拥有 Servlet、租户模型、SQL 或认证实现 |
| MVC | `Field`/`FieldList`/`FieldContract`、`FieldValues`、`Style`、`RawResponse`、`RequestIdAccessor`、`ErrorStatusResolver` | 请求缓存、来源选择、聚合校验、响应包装、异常到 HTTP 映射 |
| Data JPA | `BaseLongEntity`、`BaseRepository`、`SqlTemplateSource`、`FreemarkerSqlRenderer`、`JpaSqlTemplate` | 模板渲染与查询执行；结果投影是内部组件，不扩展成任意对象映射 |
| Security | Spring Security 主体语义、JSON 401/403、`SecurityAuditLogger`，通过自动配置接入 OAuth2/OIDC | 资源校验和可选授权服务；不拥有企业成员、Product Session、Agent 权限模型 |

Common 可以依赖其使用的基础库，不承诺零依赖；这里约束的是业务与能力归属。只在确实存在替换实现时设置 seam，例如 SQL 模板源、Spring 安全仓储、审计记录器。未出现跨模块消费者的 Customer DTO 保持与 Customer 同包，不人为扩大公共 Interface。

## 4. 请求、数据与错误链路

### 应用 API

1. 请求进入应用，Summer MVC 生成或规范化 requestId，通过请求属性、响应头和 MDC 关联处理记录。
2. Security 资源链执行身份校验，业务方法以独立 read/write scope 做最终授权。
3. MVC 按 PARAM/JSON/PATH 字段契约导出类型化值；目标用法由框架自动推断来源。Bean Validation 负责 DTO 与跨字段约束，JSON presence 与显式 null 分开处理。
4. Customer Controller 调用 CustomerService；Service 负责事务与业务编排。Repository 负责写入/简单读取，CustomerQuery 集中拥有 SQL template、读取配置与查询指标。
5. 普通应用 JSON 返回统一响应；DELETE 成功维持 204 空响应。框架错误采用 `SUMMER_`，业务失败采用自身命名空间与传输无关 ErrorCategory。

请求关联保持独立职责，请求体缓存按 ADR 0021 由 MVC 自动管理，无须开发者显式开启；当前代码仍保留旧缓存开关及关闭时的 JSON 契约启动检查，迁移须同步移除。SQL 投影仅支持标量、Map、Record/构造器 DTO、Spring Data 接口投影和 Tuple；不支持 setter Bean、依赖列顺序的 List。

### 协议请求

OIDC discovery、authorize、token、logout、form login、原始 `/csrf` 使用各自原生协议，不参与业务 envelope 解包。Actuator 和文件/字节流/Range 同样保留自身语义。代理路径与具体安全策略见 [安全模型](OAuth2-OIDC安全模型.md)。

### Customer 目标契约

不可变 username 是公开资源标识；customerId 是内部 ID；email 为可修改且唯一的联系方式；displayName 必填；active 是可恢复启停。Customer 与 authenticated principal 没有本次范围内的关系。物理删除后 username 可以复用。

该契约由 [ADR 0016](../adr/0016-identify-customers-by-username.md) 和 [Issue #69](https://github.com/abluepoint/summer/issues/69) 定义。当前实现仍为 email，迁移须同步实体、Repository、查询、API、种子、UI 和 PostgreSQL 测试，不能只改路由名。

## 5. Summer UI 目标结构

前端路径为仓库根下独立的 `summer-ui/`。实际目录组织继承届时固定的官方 Arco Design Pro React/Vite commit、包管理器与 lockfile；本次不凭空规定与上游冲突的工程目录。

当前前端职责集中在四处：OIDC 客户端及内存认证状态、`/api/**` 请求适配与 `SummerApiError`、Customer 路由/表单、官方 locale 和菜单。协议交互使用 `oidc-client-ts`；只有 `CustomerForm` 已获准作为共享自定义组件。后续 AICT 页面也在 `summer-ui/` 内演进，其业务路由、服务端契约和认证边界须逐项落实，不能把旧独立原型直接当作已完成产品。

Drawer、Modal、路由页面三种创建/编辑模式使用同一契约；列表状态由 URL query 驱动，默认进入 `/customer/drawer`。保留的上游页面归入“Arco Pro 示例”，开发 Mock 仅服务上游示例，Summer API 和安全请求始终访问真实后端。

前端 scope 控制服务于界面行为，后端授权仍是最终裁决。400/409 映射表单字段，401 最多重启一次 PKCE 且不重放写操作，403 保留认证，错误保留 requestId。完整交互及测试场景引用 Issue #69，不复制第二份需求规格。

## 6. 部署、存储与运维

| 运行单元 | 构建/数据 | 部署责任 |
| --- | --- | --- |
| Sample | Gradle/Java 21；可丢弃开发库，真实验证用 PostgreSQL | 框架参考后端；演示客户端、身份、JWK 不直接作为生产设施 |
| Summer UI（目标） | 独立 Node/Vite；access/ID token 只在内存 | 开发 Vite proxy；生产同一 HTTPS origin 静态资源与反向代理 |
| 外部生产应用 | 消费发布的 Starter；自行拥有数据库迁移 | 持久化身份/客户端/授权/密钥、运维与容量管理 |
| AICT IAM/BFF/连接服务（服务端） | 自有 IAM 业务库、BFF 会话、连接凭据存储 | 服务端分开管理安全投影与物理执行；前端统一由 Summer UI 承载，BFF 安全契约仍须单独对齐 |

后端 JAR 不嵌入 UI dist；生产 issuer、redirect、post-logout redirect 由环境提供。当前整理不新增容器、Kubernetes、云或 CI/CD 定义。框架提供 requestId、结构化安全/数据事件及 Actuator；产品审计账本和发布控制面归应用所有。

## 7. 质量门禁与演进

依赖白名单、Modulith 检查、行为测试和真实浏览器 E2E 各验证不同事实，不能互相代替。现有检查通过不代表最新决策已实现，也不能证明 AICT 产品逻辑符合框架归属。

先隔离应用归属和通用安全语义，再完成 Customer 与 public client 契约，最后构建 UI 和真实联调。具体阶段、验收与回退见 [summer4 迁移计划](../guides/summer4迁移计划.md)。
