# Summer 4 模块边界

## 允许依赖

```text
summer-dependencies
├── summer-common
├── summer-mvc          -> summer-common
├── summer-data-jpa     -> summer-common
├── summer-security     -> summer-common
├── *-autoconfigure     -> 对应能力模块
├── *-starter           -> 对应 autoconfigure
└── summer-boot-starter -> 四类 starter
                           └── summer-sample
```

根任务 `verifyModuleBoundaries` 读取所有 Gradle `ProjectDependency`，任何未列入白名单的依赖都会使 `check` 失败。能力模块禁止依赖 autoconfigure 或 starter；能力 starter 不得反向依赖聚合 starter。

## Spring Modulith 边界

示例应用包含以下应用模块：

- `shared`：跨模块稳定 DTO/API。
- `customer`：客户实体、Repository、模板查询、受保护 Web 端点；只允许依赖 `shared`。
- `operations`：公开运行信息入口，不依赖客户内部实现。

`ModulithArchitectureTest` 执行 `ApplicationModules.verify()`，循环依赖、未声明跨模块访问和其他结构违规会阻断测试。

## 演进规则

1. 新框架能力先建立独立 capability module，再增加 autoconfigure 和 starter。
2. 应用模块跨边界只使用公开 DTO、事件或接口，禁止引用对方内部实体/Repository。
3. 版本只进入 `gradle/libs.versions.toml` 或 `summer-dependencies`，子模块不写核心框架版本。
4. `check` 必须同时运行 Gradle 边界任务与 Modulith 架构测试。
