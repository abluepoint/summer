# 业务字典01：生效读取升级（#191）

## 运行边界

Summer Sample 的 V39 将旧的“已发布、启用、无指针且无历史”的字典按租户物化为版本1。
项按原 `sort_order,item_value` 排列；停用项保留在快照内，旧公开列表和单项有效性读取仍排除停用项。
已有历史原文、序号和所选指针不修改。旧快照缺少说明时解码为空字符串，缺少组时解码为空数组。
新管理入口 `/dictionary/manage` 读取基础生效快照，原 `/dictionary/form` 继续消费组织覆盖后的选项。
管理列表仍是编辑数据列表，不能把它当生效内容使用。

普通创建必须建立草稿（`published:false` 或不传）。普通更新不能切换 `published`；使用现有
`POST .../publish`、`.../disable`、`.../rollback` 操作和 `expectedVersion`。
元数据的公开标记和启用状态先保存为草稿，发布后才影响公开读取。
旧单项接口仍是可选有效性检查，不能用它读取已停用项的名称。
覆盖保存、发布和回滚统一校验基础生效快照的可选项，不能引用草稿专有值。
旧公开 `version` 保留原义；新增 `publishedVersion` 是基础发布版本，`publishedRevision`
是覆盖的实际发布修订。`effectiveToken` 区分基础和覆盖来源；覆盖草稿保存不会改变它。

## 升级前

1. 停止本租户字典与覆盖写入，记录应用版本、迁移版本、数据库版本和UTC检查点。
2. 使用既有受控备份设施备份完整业务库（包含 Flyway、字典、项、历史、覆盖与覆盖修订、审计、outbox、通知）。
   密码只通过受控Secret或安全输入消费，不进入命令行、日志或本文件。
3. 在恢复演练库验证备份能打开，核对行数、租户复合唯一键、历史原文字节摘要和指针。
4. 预检 `published_version` 所指版本在同租户是否存在、无指针但有历史的记录、覆盖项是否属于基础生效快照。
   原始引用需要运维授权后核对，不将业务值导出到共享日志。
5. 应用自定义Flyway只接入 `spring.flyway.locations`，不支持通过 `spring.flyway.target` 构造旧版演练。
   演练旧结构应使用原始V1–V38迁移资源夹具目录；不要改写原迁移或恢复活动源码。

## 检查点与异常

V39先保存 `summer_dictionary_v39_{type,item,version,override}_backup`，再建立异常清单、物化快照、建立指针。
这些库内备份用于逐行核对，不代替完整库备份，也不承诺具备原索引与约束。
MySQL DDL会提交；不要把迁移整体视为可回滚事务。

`summer_dictionary_upgrade_issue` 保留缺失指针目标、无指针历史、覆盖无基础及基础快照外的覆盖项。
旧控制字段曾关闭/私有化现有快照而与快照不一致时，记录 `LEGACY_CONTROL_DIFFERS_FROM_SNAPSHOT`，
将发布控制关闭，保留原历史与指针，防止升级重新公开；整理后通过专用发布操作恢复。
异常记录不删除、不造项、不回退编辑行。升级后必须检查该表并对每项形成整理记录；无指针或
缺失快照的公开读取失败关闭。覆盖投影只允许基础可选且当前可见的项，关闭或私有基础始终阻止覆盖公开。
异常清单非空的租户不得标记为升级验收通过。

迁移成功后核对：

- 原有历史行数、原文摘要、版本号、租户同码隔离和指针没有变化。
- 每个新增版本对应一条原生效字典；未发布/关闭记录没有新增生效指针。
- 库内备份行数与升级前检查点一致，新快照名称、公开标记、启用状态和项排序与原生效数据一致。
- 浏览器管理页显示原生效名称，编辑行更改不能影响公开选项；旧单项校验、私有、关闭、隐藏覆盖与越权拒绝仍成立。
- 首次新发布采用历史最大版本号加一；重启后Flyway验证和同样的读取核对可重复。

## 失败与恢复

先停止本次应用的字典写入并保留失败迁移状态、异常清单及全部备份，不盲目重跑脚本或执行 Flyway repair。
若DDL已提交但数据回填失败，使用演练验证过的完整库备份恢复到新的隔离数据库，核对检查点的原文摘要、
行数、约束、指针与覆盖修订后再切换连接。未经核对不能在活动库中删除迁移行或清除备份表。
若只需纠正数据异常，在受控维护窗口记录逐条整理方案及审批，再在恢复演练库重放升级并提供差异证据。
程序版本降级不等于字典内容回滚；不承诺旧二进制读取未来新快照格式。

本票真实执行、失败批次、恢复核对和浏览器证据见对应执行目录的 handoff.json；本说明不是测试通过证明。
