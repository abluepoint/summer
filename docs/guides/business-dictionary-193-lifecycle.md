# 业务字典发布、历史与回滚

管理页默认显示基础生效快照；草稿与历史通过页签进入，生效与历史内容只读。草稿保存后点击“核对并发布”，检查名称、公开/启用状态、全部项的说明、启停及默认顺序，然后确认发布。未发布或停用时不显示草稿代替生效内容。历史详情遵守当前管理读取权限及项数据范围，回滚保持当前草稿。

发布请求必须包含 `expectedDraftRevision`、`expectedVersion`、`expectedEffectiveRevision`；停用和回滚包含后两项，回滚另带 `targetVersion`。三项期望字段必须是 JSON 非负整数（目标版本同样禁止字符串、布尔及小数转换），非法或缺失返回参数错误，合法过期返回409及requestId。旧 `version` / `revision` 别名只代表 `expectedVersion`，不能替代草稿或生效修订。通过管理草稿读取取得三项值；停用后 publishedVersion 保留历史指针，effectiveRevision 仍递增。

`draftRevision` 只保护编辑。`publishedVersion` 可以回退；`effectiveRevision` 每次成功发布、停用或回滚递增，重放不递增。新发布取全部历史最大号加一，回滚选择原历史号，不重写历史与草稿。原有公开 `version` 覆盖语义保留；新增 effectiveRevision 和 opaque effectiveToken 区分基础生效身份，覆盖仍按组织、租户、基础优先级。

幂等键为可选的非空字符串，最多255字符，放在请求体 `idempotencyKey`；重试必须保留完整原请求。服务端先检查当前授权，再匹配主体、租户、资源、动作及期望字段/目标版本，返回持久化的原提交响应。同键变更语义返回409，旧无完整收据的键也拒绝冲突，避免猜造响应。历史或幂等原结果包含当前不可见项时拒绝，不回显原文。

快照格式1包含本阶段元数据、全部项的值、名称、说明、默认位置与启停，groups为空（任务04扩展）。旧格式缺省说明/分组仍可读取。草稿保存和发布对同一结构按UTF-8序列化执行 **512 KiB** 上限，超过返回参数错误且整笔写入回滚；不是Java字符数。该内容上限低于现有1 MiB HTTP请求传输上限；传输限制仍可独立拒绝过大请求。MySQL V41将快照列保持为LONGTEXT，并新增生效修订与outbox原请求摘要/原结果列。历史原文不改写、不截断。任务04加入组时必须继续复用同一完整快照容量校验。

V41为追加迁移：原有指针和发布内容保持，effectiveRevision初始为0，首次新生命周期操作后递增。上线前保留类型、历史及outbox备份；DDL不可假定整体事务回滚。恢复时停新写入，使用升级前整库/表快照及对应旧程序共同恢复，不能只删除列或将新程序旧快照混用。隔离迁移与恢复核验证据以任务03执行目录为准，未执行的生产灾备不能算通过。
