# 业务字典组与整体版本

首层菜单“字典与字典组”下分别提供“字典管理”和“字典组管理”。字典组入口 `/dictionary/groups` 沿用全局活动企业，统一列出各字典的组，每组一行，分别显示组的启停状态和发布状态。新建时选择所属字典，已有组可从列表查看详情或编辑草稿。字典管理页面仍仅维护字典及字典值。

字典组草稿支持新增、改名、启停、通过“添加字典值”表格跨页勾选多个成员及调整组内顺序；保存时保留字典元数据、字典值和默认排序。组引用同字典的项，不复制显示名称和说明；同一项可加入多个组。新组首次保存按当前默认顺序初始化，保存后可独立调整；后续新增成员追加组尾，改变默认顺序不会重排组。保存、冲突处理、未保存离开保护和发布沿用所属字典的整体草稿流程；发布核对列出全部组，再按字典值逐行展示所属组及组内顺序。

既有草稿读取/保存端点兼容增加 `groups`：每组具有稳定 `id`、`code`、`name`、`enabled`、只读 `everPublished` 和有序 `memberIds`。新增组使用客户端临时 `new:` 标识，保存响应替换为服务器 UUID；新增项的临时标识也会一并解析为成员引用。编码沿用字典编码约束，在所属租户、字典内唯一。省略 groups 的旧草稿请求保留组；显式空数组表示删除全部草稿组，曾发布组不能这样删除。

组/成员变化共享已有 expectedDraftRevision 和原子草稿保存事务，按差异检查创建、修改、启用/停用能力及 OAuth scope。完整维护必须能访问所有项；部分可见列表不能覆盖全量。草稿与生效组的成员输出过滤当前不可见项，历史完整内容在维护范围不足时拒绝。组没有独立发布入口或版本。

组一经发布，code 与组身份不可删除或修改；可通过后续版本改名、停用。该依据由发布事务持久化，不因回滚解除。写事务通过数据库当前锁读取得曾发布身份，避免发布完成后，等待中的旧 RR 读取视图绕过保护。

快照格式 2 在原元数据、项、默认排序上增加完整 groups。每组包含 id、code、name、enabled、有序 memberValues；memberValues 是同一快照项值的引用，显示名称和说明始终来自 items。生效、历史、发布核对展示全部结构；回滚选择原历史完整快照，当前草稿保持原状。旧缺少 groups 的快照解码为空组，不改写原文或历史号。沿用 512 KiB UTF-8 整体内容上限与三项发布期望字段。

MySQL V42 只追加组/成员表及项复合身份唯一键。成员同时以租户、字典、组和项的复合外键约束，阻止跨租户/字典引用，唯一键拒绝重复组编码和重复成员。旧字典不自动生成组。升级前备份类型、项、历史、Flyway 历史及数据库结构；DDL 不假定整体事务回滚。恢复应停写并使用升级前完整检查点与相应程序，不直接删除已有组数据后继续运行新程序。

分组选项消费由后续任务 06 交付，本票未新增公共分组读取端点。现有公开选项的缓存、降级与组织覆盖路径继续使用完整生效快照的原有项投影；管理组读取不缓存草稿，仍逐次检查访问范围。
