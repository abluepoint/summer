## 问题与行为

原任务执行方法把整个耗时处理器包在一个事务中。其他节点和 SSE 查询只能在任务结束提交后看见开始、尝试与进度，不能驱动执行中的页面。新回归在处理器仍运行时查询事件及 HTTP SSE，原实现失败。

执行改为短事务领取、开始尝试、进度写入及结束尝试，处理器在事务外运行。领取时锁定任务定义和已有执行记录，每次调用使用独立所有者标识；旧所有者不能覆盖接管后的最终状态。接管会把中断尝试记为 `TASK_NODE_LOST`，即使中断发生于最后一次尝试，也会允许一次恢复执行。业务幂等键仍传给受信任处理器，外部副作用的幂等责任没有被数据库执行记录替代。

SSE 原实现还在发送期间持有全局锁，慢订阅者会阻塞任务进度持久化。有效红灯为进度写入超时。修复后发布只写数据库，发送使用固定四线程、64 个待处理项的有界队列；每连接最多一个交付任务。队列满时关闭连接，由客户端重连恢复。连接限额为每租户 32、全局 256，完成、超时、错误及服务关闭均回收名额。心跳随连接交付每 15 秒发送，连接生命周期上限仍为 30 分钟。

重放在数据库最多读取最新 501 条，实际重放最多 500 条。超出保留窗口或客户端游标超过服务端最新事件时发送 `resync`，页面重新查询执行历史。事件只包含任务/执行标识、状态、进度、尝试次数及固定脱敏日志，不包含任务参数。

手动触发的幂等记录原先可能先保存、后因 Quartz 故障入队失败；相同键重试会直接返回成功而没有执行。有效红灯验证第二次调用没有再次调度。现在保留预留记录，未出现执行记录时允许重新入队；Quartz 手动触发器按租户和幂等键确定名称，跨节点重复入队由唯一触发器约束处理。内部 Quartz 恢复任务每 5 秒最多检查 100 条尚未开始的活动任务预留记录，重启或暂时故障后继续派发，最终执行仍通过同一业务键领取。

任务恢复不再只扫描演示租户，启动时重建所有活动任务；审计写入实际任务租户。接口权限仍由当前 HTTP 授权边界和 scope 检查执行，不以租户名称格式代替授权。

任务页面新增版本化编辑、取消确认与离开保护，保存失败保留草稿和请求关联标识。写入期间互斥，暂停任务不能立即执行。未确认的触发失败再次提交沿用同一幂等键，成功后下一次明确执行使用新键。活动租户只取已认证成员选项，切换后重建页面及串流；旧执行历史响应不能覆盖已收到的新进度。
