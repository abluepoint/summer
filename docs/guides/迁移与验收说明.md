# Summer 4 迁移与验收说明

本页保留最初 Summer 4 后端迁移的构建基线与门禁。按最新 ADR 0014–0016 的整体整理见 [summer4 迁移计划](summer4迁移计划.md)；本轮实际执行结果见 [现状与目标差异](../architecture/现状与目标差异.md)，不能把下列验收命令当作已执行记录。

## 构建基线

- Java toolchain：21。
- Gradle Wrapper：9.0.0，Kotlin DSL。
- Spring Boot：4.0.7。
- Spring Cloud：2025.1.2。
- Spring Modulith：2.0.7。
- 源码版本：`4.0.0-SNAPSHOT`。

版本单点位于 `gradle/libs.versions.toml`；`summer-dependencies` 导入 Boot、Cloud、Modulith BOM 并约束全部 Summer 发布模块。

## 迁移约定

- 核心模块旧源码已清理，历史实现通过 Git 历史追溯；`summer-sample` 的旧 Maven POM、旧示例与旧 SQL 已删除。
- Summer 4 所有模块统一使用 Gradle 标准源集：生产代码与资源位于 `src/main`，测试位于 `src/test`。
- `summer-parent` 与 `summer-automator` 已从活动分支移除；历史实现通过 Git 追溯。
- 新业务只接入 Gradle 模块和 starter，Gradle 是唯一活动构建入口。

## 验收命令

```bash
./gradlew clean check
./gradlew publishToMavenLocal
./gradlew :summer-sample:bootJar
```

`check` 必须包含并通过：模块注册与依赖白名单、循环依赖和未登记模块检查、公共能力单测、请求关联与请求体重复读取、SQL 渲染、窄化结果投影、Spring Modulith、真实 PostgreSQL Testcontainers、OAuth2 令牌签发、受保护 SQL 查询、401/403/校验响应和 Actuator 健康/指标。模块门禁失败时会报告违规模块、目标依赖及完整环路径。

## 已知边界

- 示例使用内存客户端/用户与进程内临时 RSA JWK，生产必须替换为持久化或外部安全设施。
- 旧 API 二进制兼容、独立微服务部署和大规模性能压测不属于本次范围。
- 旧 Maven 构建不再是交付门禁；Gradle `check` 是后端核心验收入口。Summer UI 另有独立静态检查、单元测试、构建、真实 E2E 与浏览器审计门禁，不能由后端 check 替代。
