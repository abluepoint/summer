# 业务字典完善技术规格

## Problem Statement

现有业务字典已经提供字典与字典项管理、公开选项读取、不可变发布快照、停用和回滚，以及租户/组织覆盖、缓存和更新通知。但使用方仍需自行请求选项、转换显示名称并处理旧值；字典项缺少说明，字典组和组内独立排序尚不存在，级联选择也没有统一封装。

现有“字典项排序”无法同时表达完整字典的默认顺序和不同业务分组的顺序。将级联直接改成字典项父子树会增加主体结构的复杂度。另一方面，部分旧入口仍支持无快照的已发布字典直接读取编辑行，普通管理写入能改变发布状态，组织覆盖又有独立的版本，这些路径必须与新版本规则统一，避免草稿、历史版本或不同来源的数据被拼装成当前生效内容。

本规格沿用已经逐项确认并整体确认的业务设计，完善现有功能；同步机制优化后置。

## Solution

保留字典、字典项和字典组三个主体。字典项保持扁平，使用字符串值、显示名称和说明；字典组是同一字典内的命名子集，同一项可加入多个组。字典默认排序与每个组的组内排序分别维护，管理界面统一通过拖拽调整。

一个字典的全部内容形成一个不可变发布版本，字典项、默认排序、全部组、组成员及组内排序一起发布、一起回滚。管理页面通过“生效版本 / 草稿 / 历史版本”页签切换，默认展示生效版本；业务组件也默认只使用当前生效版本。草稿保存校验修订号，发布同时校验操作者看到的草稿修订号与当前生效版本。

前端提供名称转换与展示、普通选择、级联选择三类入口，共用字典读取能力。跨字典级联由页面配置“上游值 → 下游字典组”，组件执行；字典管理不增加通用关联模型。

详情名称转换包含生效版本中的停用项，新选项读取排除停用项。表单回显保留停用旧值并标记状态；生效版本中找不到的旧值保留原值并标记“未识别”。权限拒绝和加载失败单独处理。现有字典接口、组织覆盖、审计、缓存和通知通过明确的适配与迁移继续使用。

## User Stories

1. As a 字典管理员, I want 在现有字典功能中维护业务词表, so that 不必创建另一套重复的字典系统。
2. As a 字典管理员, I want 为字典项维护值、显示名称和说明, so that 业务使用者能够理解每个选项。
3. As a 业务开发者, I want 字典值统一使用字符串并保留前导零, so that “1”和“01”不会被隐式合并。
4. As a 字典管理员, I want 在一个字典内建立命名分组, so that 不同业务场景可以选择不同的选项子集。
5. As a 字典管理员, I want 同一字典项加入多个分组, so that 值、名称和说明只维护一份。
6. As a 字典管理员, I want 维护完整字典的默认顺序, so that 未指定分组的选择组件有稳定顺序。
7. As a 字典管理员, I want 为每个组维护独立顺序, so that 一个组的调整不会重排其他组或完整字典。
8. As a 字典管理员, I want 在草稿列表中拖拽排序, so that 可以直接调整展示顺序。
9. As a 业务开发者, I want 通过字典编码和稳定的组编码引用分组, so that 组改名不会破坏页面配置。
10. As a 字典管理员, I want 已发布的项值和组编码受到不可修改、不可删除的约束, so that 已有业务引用保持稳定。
11. As a 字典管理员, I want 删除从未发布过的草稿项或草稿组, so that 可以修正尚未生效的编辑内容。
12. As a 字典管理员, I want 通过停用让已发布项或组退出新选择范围, so that 不必删除已有引用。
13. As a 字典管理员, I want 默认查看当前生效版本, so that 看到的内容与业务消费一致。
14. As a 字典管理员, I want 切换到草稿页签进行编辑, so that 未发布修改不会影响正在使用的字典。
15. As a 字典管理员, I want 从历史版本页签查看完整历史内容, so that 回滚前可以检查目标内容。
16. As a 字典管理员, I want 字典项和全部分组作为一个版本发布, so that 消费方不会读到相互不匹配的结构。
17. As a 字典管理员, I want 一次回滚切换全部字典内容, so that 默认排序和各组顺序一同恢复。
18. As a 字典管理员, I want 回滚后继续发布时使用新的历史序号, so that 不覆盖原有发布记录。
19. As a 字典管理员, I want 过期的草稿保存被拒绝并提示刷新, so that 不覆盖其他人的修改。
20. As a 字典管理员, I want 发布时同时检查草稿修订号和生效版本, so that 发布的是自己已经查看过的内容。
21. As a 字典管理员, I want 发布和回滚重试具有幂等结果, so that 网络重试不产生重复版本或证据。
22. As a 业务使用者, I want 详情按当前生效版本转换名称, so that 字典改名后旧记录也采用当前名称。
23. As a 业务开发者, I want 普通业务记录无需额外绑定保存时的字典版本, so that 字段存储保持简单。
24. As a 业务使用者, I want 停用项仍能在旧记录详情中显示名称, so that 历史记录保持可读。
25. As a 业务使用者, I want 编辑旧记录时保留停用的选中值并看到状态标记, so that 字典维护不会悄悄清空表单数据。
26. As a 业务使用者, I want 找不到旧值时看到原值及“未识别”标记, so that 可以辨认已有业务数据。
27. As a 业务使用者, I want 新选项只包含当前可选内容, so that 不会重新选择停用项。
28. As a 业务开发者, I want 同时使用名称转换函数和展示组件, so that 详情、表格都能复用字典能力。
29. As a 业务开发者, I want 普通选择组件接受字典编码及可选组编码, so that 页面无需自行拼装选项。
30. As a 业务开发者, I want 在页面配置上游值到下游组的对应关系, so that 不需要给字典项增加父子树。
31. As a 业务使用者, I want 连续使用多级跨字典选择, so that 各级选项随上游选择更新。
32. As a 业务使用者, I want 主动修改上游后保留仍属于新组的下游值, so that 有效选择不被无故丢弃。
33. As a 业务使用者, I want 主动修改上游后清空已不适用的下游值并逐级检查, so that 不会提交不匹配的组合。
34. As a 业务使用者, I want 清空上游时清空全部下游, so that 级联状态保持一致。
35. As a 业务开发者, I want 同一访问上下文共享字典读取和名称映射, so that 表格每个单元格无需各自发请求。
36. As a 业务使用者, I want 切换租户或上游后迟到的请求不覆盖新内容, so that 页面不会显示旧上下文的数据。
37. As a 安全管理员, I want 新组件与新接口遵守既有接口权限、数据范围和组织覆盖规则, so that 新功能不扩大数据可见性。
38. As a 审计人员, I want 发布、停用和回滚继续具有统一审计及请求关联记录, so that 业务变化可以追踪。
39. As a 现有接口调用方, I want 原公开选项接口继续过滤不可选项, so that 升级后的选择行为有明确的兼容边界。
40. As a 业务开发者, I want 使用独立名称解析能力读取停用项名称, so that 无需把旧的有效性校验接口改成另一种含义。
41. As a 运维人员, I want 没有发布快照的旧字典得到受控迁移, so that 旧数据继续可读且草稿不再直接暴露。
42. As a 运维人员, I want 新程序可以读取缺少说明和分组字段的历史快照, so that 历史版本不会因格式升级失效。
43. As a 配置管理员, I want 已有租户与组织覆盖继续生效, so that 字典组上线不破坏已有覆盖配置。
44. As a 运维人员, I want 既有缓存失效和通知行为得到必要回归, so that 新读取能力不会使用错误版本或跨租户内容。
45. As a 业务使用者, I want 加载失败、无权读取、停用和未识别具有不同状态, so that 能够采取正确的处理动作。
46. As a 业务开发者, I want 缺失或停用的组不会自动退回完整字典选项, so that 页面配置的选择范围保持明确。
47. As a 运维人员, I want 迁移检查指出旧数据和覆盖中的不一致引用, so that 升级过程不会静默删除或猜造业务数据。
48. As a 维护者, I want 新功能留在现有业务字典和 Summer UI 边界内, so that 不增加无必要的框架能力模块。

## Implementation Decisions

### D01—D05：主体、存储与排序

- **D01 归属与复用。** 后端继续由 Summer Sample 的业务字典职责承载，演进现有 DictionaryService、DictionaryVersionService、PublishedDictionaryReader 及其数据访问组件；Summer UI 承载管理界面和消费组件。不创建第二套字典库，不将这些业务资源搬进 Summer Common 或新增框架 Starter。既有 dictionary type 表代表业务字典，物理命名无需为术语统一而重建。
- **D02 字段契约。** 字典项继续使用 value、label、sortOrder、enabled，新增可选 description；label 对应“显示名称”，不另建一份名称字段。值统一为字符串，保留现有 80 字符存储边界及安全字符集合，补齐单字符值的校验，禁止隐式数字、布尔、大小写或前导零转换。名称沿用 200 字符约束；说明为空时返回空字符串，最大 2000 字符。组包含 code、name、enabled，编码复用字典编码的规范并在所属字典内唯一。
- **D03 分组关系。** 新增字典组及组成员关系，成员引用现有字典项，不复制项值、名称和说明。关系保存独立组内位置；字典项自身位置仍表示默认排序。唯一性至少覆盖“租户、字典、组编码”和“租户、字典、组、项”；数据库关系约束及服务校验共同防止跨租户、跨字典引用。组的访问边界继承所属字典，成员仍受项的数据范围约束。
- **D04 排序写入。** 拖拽提交有序的稳定项标识列表，后端校验重复、缺失、未知项及维护范围，再在一次草稿修改内规范化保存位置。默认列表和组成员列表分别写入，不从其中一个实时推导另一个。新增组的初始排列可按当前默认顺序生成，此后独立维护；新增成员追加到组末尾。局部可见列表不得被当作全量列表覆盖，完整聚合维护和发布须具备相应完整维护范围。
- **D05 发布过的身份。** 项和组记录“是否曾发布”的持久依据，发布时原子更新，回滚不会清除。已发布项禁止改值和删除，已发布组禁止改编码和删除；名称、说明、排序及停用状态通过后续版本修改。从未发布的草稿项、组允许删除，其草稿成员关系同时清理。字典编码继续作为稳定业务引用。

### D06—D10：完整版本与并发

- **D06 快照演进。** 继续使用不可变 JSON 发布快照，增加明确格式版本。新快照包含字典元数据、全部项及说明、默认顺序、全部组、组成员及组内顺序，包括停用状态。新读取器把旧快照解码为“说明为空、分组为空”的兼容结构，旧序号及既有排序不变；不改写历史快照原文。持久化列容量随完整结构扩展，请求和持久化大小校验使用一致约束，禁止截断。
- **D07 草稿与生效状态分离。** 编辑数据继续作为草稿，字典发布状态及当前快照指针作为生效控制状态。公共读取的名称、启停和公开标记取自所选发布内容及明确的生效控制状态，不再因为修改草稿表中的同名字段而改变生效内容。实时权限和数据范围仍在每次读取时检查。已关闭的字典不能因普通编辑或组织覆盖重新公开。
- **D08 草稿并发。** 字典聚合增加独立 draftRevision。字典元数据、项、组、成员和排序的任何草稿写入，都先在同一聚合并发边界校验 expectedDraftRevision，再原子写入并递增修订号。旧入口和聚合入口调用同一个写入机制，不能只在前端校验。冲突使用统一 409 响应和 requestId，缺失或非法必填修订号使用统一参数错误。
- **D09 发布事务。** 发布同时校验草稿修订号与生效版本，并与生成快照、记录曾发布身份、分配新发布序号、切换指针、写审计、outbox 和通知记录处于同一事务边界。并发编辑或切换生效版本只能得到一致快照或冲突，不能得到半新半旧内容。新发布序号从全部历史最大值递增，不使用可回退的当前指针加一。字典增加单调递增的 effectiveRevision，每次成功发布、停用或回滚递增，幂等重放不递增；上述操作校验 expectedEffectiveRevision，防止“V1→V2→V1”使过期请求重新有效。它与可回退的 publishedVersion、仅用于草稿的 draftRevision 分开。
- **D10 回滚与幂等。** 回滚继续选择原历史发布版本，保持该历史序号，完整切换项和全部组，不创建内容相同的伪历史版本。回滚不静默覆盖未发布草稿，草稿和生效内容仍分开。发布、字典停用和回滚沿用幂等键，重试先检查授权，再校验原操作及请求语义并返回原提交结果；同键不同操作或不同内容冲突，重复请求不得追加版本、审计或通知。事务失败不产生可见发布结果。

### D11—D14：读取与接口关系

- **D11 两种读取语义。** 名称解析和可新选项均以同一当前生效内容为来源，但过滤语义分开。名称解析包含该版本内已停用且当前主体可见的项；选项读取排除停用项，指定组时按该组独立排序。组缺失或停用时返回明确不可用结果，不退回完整字典。单个字典不可读、私有、未生效或被停用时，名称解析同样不能读取其名称。
- **D12 接口边界。** 在现有企业字典资源下提供草稿读取/原子保存、生效内容读取、历史版本详情、分组选项和批量名称解析能力；继续使用既有版本列表、发布、停用和回滚职责。草稿保存显式携带 expectedDraftRevision；发布携带 expectedDraftRevision、expectedVersion 和 expectedEffectiveRevision，停用/回滚携带后两项，回滚另带 targetVersion。管理读取返回 draftRevision、publishedVersion、effectiveRevision，未发布指针按既有比较约定使用 0。历史详情只对具有管理读取权限的主体开放，业务组件默认不接受历史版本作为消费来源。名称解析一次处理同一字典的多个字符串值，返回逐值的 value、label、description 和 enabled/disabled/unknown 状态，以及整次响应的生效上下文标识；未知项不伪造名称。分组选项返回该组状态和可选项，组不可用不等同于正常空组。管理生效页展示基础发布快照，公共消费按访问组织应用覆盖，界面不把两者的版本号混为一个概念。
- **D13 旧 API 兼容边界。** 保留既有无企业前缀和企业前缀路由的正确租户解析、公开读取约束及读写权限。旧公开选项列表继续只返回可选项；旧单项读取继续作为当前可选有效性校验，停用项仍不可通过它读取，新组件改用新增名称解析能力。新增字段采用兼容扩展，不把 label 改名。旧管理列表作为编辑数据查询的兼容职责保留，新管理默认页显式读取生效视图，不把旧编辑行列表伪装成生效内容。
- **D14 有意收紧的旧写入。** 所有旧字典编辑入口必须接入聚合修订号，已存在资源的无条件旧写入不再允许；调用方需要升级以携带修订号。新建资源建立初始草稿，普通 CRUD 不再通过 published 布尔值直接发布或切换生效状态；发布、停用走受版本保护的专用操作，直接绕过者返回明确错误。旧发布请求的 version/revision 别名继续仅表示旧 expectedVersion，新增草稿修订号有独立字段，禁止复用同名概念。本次不声称旧的无版本写入或“写入立即公开”行为完全兼容。

### D15—D17：覆盖、缓存、权限与现有功能

- **D15 组织覆盖沿用原体系。** 保留 ConfigurationOverrideService 的组织优先于租户、租户优先于基础字典的既有优先级、独立发布历史及授权；字典组不是组织覆盖，覆盖版本不是基础字典发布版本。既有选项数组作为兼容覆盖投影继续读取，缺少的新说明从基础生效快照补齐。覆盖只能在基础生效快照和当前可见项范围内生效，不得引用草稿专有项或新增身份，也不能重新启用基础版已停用的项或组。分组选项取“基础组成员、基础可选项、有效覆盖选项、可见项”的交集，按组内顺序；未指定组时保留有效覆盖的默认排序。可见覆盖中的名称覆盖可用于已包含项；覆盖未包含但基础生效版仍存在且有权读取的旧值，可用基础名称完成详情回显，但不可据此加入新选项。隐藏或停用的已发布覆盖继续阻止向基础配置回退，私有基础也不能被公开覆盖绕过。覆盖编辑与生命周期各入口统一执行这些约束，不能只校验旧的便捷入口。
- **D16 生效标识与缓存。** 新读取响应区分基础 publishedVersion/effectiveRevision 与覆盖的 publishedRevision，提供反映当前有效组合的 opaque effectiveToken；无适用覆盖时明确标识基础来源。覆盖身份使用实际发布修订，不能用包含未发布编辑的最新草稿行 version 代替。旧公开 DTO 的 version 保持其已有兼容含义，新组件不能把它直接当成基础发布版本或单调递增序号。共享与缓存键至少区分租户、字典、访问主体/数据范围、基础生效状态、覆盖发布状态、读取模式和组。沿用现有版本化缓存与失效通道，成功发布后使旧组合失效；草稿保存不发布新的公共内容。现有降级读取守卫要适配新的生效身份和组/名称读取语义，不能返回旧指针、已隐藏覆盖或旧权限下的缓存。现有通知事件名、元数据语义、租户边界及续传契约保留，不增加通知协议。
- **D17 权限和错误。** 复用现有读、创建、修改、发布、停用、回滚能力及兼容 write 授权，新增聚合写入按实际变化校验相应动作，不能把创建或停用全部降成修改。完整维护受数据范围约束；读取依次校验租户成员、动作能力及数据范围，再取缓存或回显。单项不可见时不得泄露名称和存在细节。继续使用 SummerException、Parameter contract、统一响应和 requestId；新增错误使用业务域语义，不增加一套专用异常层次。只在字典成功读取后判定未知值，字典级鉴权失败或读取失败不能伪装成成功的“未识别”。

### D18—D20：前端与管理页面

- **D18 封装。** Summer UI 建立共享的上下文字典读取与名称映射能力，并提供转换函数/展示组件、普通选择组件、跨字典级联组件。组件接受字典编码、可选组编码、业务值及页面的联动配置，读取当前生效版本；不向通用组件暴露组织覆盖原始 JSON 编辑。同一上下文合并并发请求、共享已加载结果，转换函数在已加载映射上工作；不为每个表格单元格发请求，不把字典内容写入浏览器持久化存储。
- **D19 回显与级联。** 保留停用旧值并显示名称和“已停用”；成功读取却找不到的旧值显示原值和“未识别”，均不自动清空或搜索历史版。加载中、失败、无权限与空选项分开处理。用户主动改选上游时，只保留仍属于新组的下游值，清除不适用值并逐级检查；上游清空时清空全部下游。初始化旧记录不触发这套主动清空规则。切换租户、字典或上游时取消或隔离过期请求，迟到响应不得覆盖新状态；失去读取权限时按既有规则清理该上下文的服务端数据。
- **D20 管理和原页面。** 新管理页默认选中“生效版本”，另有“草稿”“历史版本”页签。生效与历史只读，草稿编辑项、说明、组和两处独立拖拽排序，明确保存与发布动作。无生效版时显示尚未发布，不把草稿填入默认页。冲突提示刷新并保留可供用户处理的编辑状态；切页和离开沿用未保存修改保护。复用现有路由 manifest、菜单和接口权限，不创建新的认证上下文。现有表单消费入口保留，以新组件替换重复逻辑；既有授权覆盖功能保留其兼容入口，与通用组件分开。

### D21—D23：数据升级、旧功能处置与交付

- **D21 升级方式。** 追加 MySQL/Flyway 升级，不改写已经执行的迁移。保留现有字典、项、租户复合键、版本、outbox、通知和覆盖记录；新增说明、组关系、草稿修订及曾发布依据。旧字典默认没有组，说明为空，默认排列保持升级前的稳定顺序；不能把组织覆盖或旧枚举猜成新字典组。曾发布依据从所有历史版本及旧生效数据建立，不能仅查看当前回滚指针。
- **D22 无快照旧字典。** 预检识别“已发布但没有快照”的旧记录，备份后将其原有生效项和顺序物化为初始快照并建立指针，避免升级后继续公开读取编辑行。已有历史和指针不重编号、不覆盖；未发布或已关闭的字典不被迁移自动启用。对基础版本缺项的旧覆盖、租户不一致或不可解释的引用形成检查清单，禁止静默丢弃、自动造项或回退草稿；受影响记录须经可追踪的数据整理后通过升级验证。DDL 与数据回填不能假设跨步骤原子回滚，采用备份、检查点和可重复核对的恢复流程。
- **D23 处置原则。** 旧字典管理、发布和回滚由统一聚合流程接管；旧读取通过兼容投影复用同一生效解析器。旧版本/审计数据保留，旧公开选项与有效性校验继续有其原义。移除的仅是绕过修订保护或直接暴露草稿的旧行为。分阶段交付先补数据与版本边界、兼容读取和写入适配，再接管理页与组件；所有调用方迁移完成前不能靠删除旧测试、绕过授权或第二套数据源制造通过。

## Testing Decisions

测试边界已经用户确认：以真实浏览器联调为最高入口，复用现有 HTTP 集成测试；真实 MySQL 验证迁移、事务与并发，缓存和通知做必要回归，不新增内部方法级测试入口。测试断言可观察行为、响应、持久化约束结果和事务证据，不通过私有方法、内部调用次数或源码形态证明业务正确；共享请求只在确有性能契约时从外部网络观察。

- **T01 浏览器主流程。** 使用真实 Summer UI、真实 HTTP 服务和真实 MySQL，完成旧字典升级后的生效页展示、草稿编辑、说明、建组复用、多组不同排序、拖拽、发布、历史查看与整体回滚；同时展示转换函数/组件、普通选择和页面配置的多级联动。验证三页签默认值和发布前后的可见内容。现有字典浏览器脚本可复用运行方式，但其拦截请求场景不算真实联调。
- **T02 HTTP 主体契约。** 扩展 DictionaryHttpTest、DictionaryVersionHttpTest、DictionarySelectedItemHttpTest 等已有 HTTP 入口，验证字符串单字符及前导零、说明、组唯一性、成员同字典约束、独立顺序、已发布身份限制、草稿删除和停用。新名称解析能读停用项，旧单项有效性接口仍不可；未知值仅在成功且有权读取的字典中按约定返回。
- **T03 真实并发与事务。** 两个客户端并发保存、保存与发布竞争、并发发布、回滚后的再发布及停用/回滚形成的状态令牌变化均从 HTTP 触发，在真实 MySQL 上核对成功/冲突、完整快照、修订号和证据数量。注入可控持久化或审计失败，核对无半套版本、无部分组更新和无重复证据；幂等重试返回原结果，同键不同请求冲突。H2 或串行断言不能代替这些证据。
- **T04 真实升级。** 参照 DictionaryMySqlIntegrationTest，准备旧结构与数据夹具，覆盖无快照生效字典、未发布字典、关闭字典、已有多版本、旧快照缺字段、租户同码、组织覆盖及异常引用。执行真实迁移，比较值、名称、顺序、可见范围、历史原文和版本号，验证恢复检查点及首次新发布。Docker/数据库门控未执行时明确记为跳过，不能当验收通过。
- **T05 组件状态。** 从浏览器验证停用旧值、未识别值、加载失败、无权限、清空和主动联动；旧值初始化不能误触发主动清空。迟到响应、切租户和取消请求等难以稳定复现的竞态，可以复用现有浏览器请求拦截夹具补测，但与 T01 的真实联调证据分开记录。
- **T06 授权回归。** 经真实权限和数据范围入口验证查看、创建、修改、发布、停用、回滚分别拒绝，聚合更新不能越权，跨租户及隐藏项不能引用或泄露。撤权后不可继续从共享数据、缓存或降级值取得旧内容；字典级私有/关闭不被新名称解析或公开覆盖绕过。
- **T07 覆盖兼容。** 验证组织＞租户＞基础优先级、隐藏覆盖阻止回退、原数组覆盖解码、覆盖发布身份不随未发布编辑变化、组成员与覆盖交集、组内排序不被覆盖排序改写，以及覆盖不引用草稿项、不复活基础停用项/组。新组件与旧公开选项在各自承诺语义内使用同一有效来源。
- **T08 缓存与通知必要回归。** 复用现有版本化缓存和字典通知 HTTP/SSE 用例，验证提交后刷新读取、回滚不误判为过期响应、通知仍仅含原有元数据、raw SSE/续传和租户授权不退化。更新守卫后，过期快照、隐藏覆盖及旧权限的降级值不得被返回；不为本功能重新建设全套同步压力测试。
- **T09 工程检查与证据。** 运行受影响后端既有回归，以及 Summer UI 的相关行为测试、类型检查、lint 和构建。纯源码正则检查只作辅助，不代替行为验收。逐批报告实际执行、失败、错误、跳过及真实环境范围；本规格中的测试均为后续要求，不是已执行结果。

## Out of Scope

- 优化多节点同步、重建消息通道、增加新的实时通知协议或同步压力平台。
- 字典项父子树、树形组、通用跨字典关系表或后台联动规则引擎。
- 联动映射的后台集中维护；映射继续属于业务页面配置。
- 字典组独立发布版本、跨字典原子联合发布或给普通业务记录绑定历史字典版本。
- 自动检索旧版本给未知值补名称、自动改写业务记录、自动将字符串值转换为数字或布尔值。
- 已发布项/组的物理删除、已发布值/编码的复用或原地修改，以及改写历史快照；显示名称与组名称仍可通过新版本修改。
- 把业务字典改造成新的 Summer 4 框架模块、重做身份认证或重构系统参数全部功能。
- 任意旧二进制程序读取新快照格式的降级保证；字典内容回滚不等同于程序或生产数据库降级。
